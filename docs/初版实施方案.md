# 开机待办（今日待办提醒）初版实施方案

- 文档版本：v0.1
- 日期：2026-09-16
- 目标：Windows 开机（登录）后自动启动，用小窗口询问"今天要完成什么"，并把结果本地留存、次日可续。

## 2. 技术选型

| 方案 | 依赖情况 | 冷启动 | 观感 | 结论 |
| --- | --- | --- | --- | --- |
| **Python + tkinter** | Anaconda 自带，零安装 | 约 0.6~1.0s | 朴素但够用 | ✅ **MVP 首选**（依赖风险最低、迭代最快） |
| Python + PyQt5 | 本机已装 5.15.10 | 约 1.2~2.0s | 精致，可做圆角/动画/无边框 | ⭕ 外观升级路径，M3 之后再考虑 |
| PowerShell + WPF | 系统自带 | 约 1~2s | 原生 | ⭕ 备选，脚本签名与调试体验差 |
| Electron / Tauri | 无 npm，需引入 Node 工具链 | 1~3s | 最好 | ❌ 对自用小工具过重 |
| C# WPF | 未安装 .NET SDK | 最快 | 好 | ❌ 需先装 SDK，收益不成正比 |

**推荐：Python 3.12（Anaconda）+ tkinter + 标准库，`pythonw.exe` 无控制台启动。**

理由：当前环境已全部具备、启动快、无外部依赖、改一行代码即生效；且日后若要换成 PyQt5 界面，业务层代码可以原样保留。

## 4. 交互设计细节

### 4.1 窗口

- 尺寸约 420×340，**置顶**，出现在屏幕右侧（默认右下、离任务栏留 24px），记忆上次位置与大小。
- 单窗口双模式：**询问模式**（首次弹出）与**清单模式**（当天已记录时查看/勾选），避免堆多个窗口。
- 无边框自定义标题栏（可选），但保留常规最小化/关闭能力；关闭 = 保存并隐藏，不做二次确认。
- DPI 感知：按系统缩放渲染，避免高分屏下字发虚。

### 4.2 主流程

1. 登录后延迟出现窗口，标题带日期与星期：`今天是 2026-09-16 周三 — 今天要完成什么？`
2. 顶部显示**候选区**：
   - 「昨日未完成」：一条一个复选框，勾选即带入今天（默认全部未勾，用户自己挑）。
   - 「常用模板」：可配置的固定短语（如"晨会""写日报""运动"），单击追加一行。
3. 中部为**输入框**（多行）：`Enter` 提交一条并清空，`Shift+Enter` 换行。
4. 已有条目在下方**清单区**：复选框 + 文本 + 删除；支持双击改写。
5. 底部按钮：`保存并关闭`、`稍后提醒`（15/30/60 分钟或"今天不再提醒"）、`今天先跳过`。

### 4.3 打扰策略（关键，决定这工具会不会被你自己关掉）

- 每天最多**主动打断一次**：当天已有记录时，不再强弹录入窗口，仅显示清单或静默。
- 多次登录/解锁不会重复弹出（用"当天是否已弹过"标记，而非进程生命周期）。
- `稍后提醒` 用一次性定时器实现，不做系统级通知；错过则下次登录再提示。
- 窗口 10 分钟无输入 → 自动保存并关闭，不丢已输入内容。
- 全程不联网、不调用计划任务、不写注册表（MVP 阶段），随时删掉 `.lnk` 即可彻底停用。

## 5. 数据设计

按天一个 JSON 文件，人类可读、可 git 追溯、单文件损坏不影响其他天：

```json
{
  "date": "2026-09-16",
  "created_at": "2026-09-16T08:35:12+08:00",
  "updated_at": "2026-09-16T09:10:44+08:00",
  "asked_at": "2026-09-16T08:35:20+08:00",
  "items": [
    {
      "id": "a1b2c3",
      "text": "把方案初稿发给老王",
      "done": false,
      "done_at": null,
      "created_at": "2026-09-16T08:36:01+08:00",
      "carried_from": null,
      "tag": null,
      "note": ""
    }
  ]
}
```

写入规则：临时文件 + `os.replace` 原子替换；读取时 JSON 解析失败则把原文件改名为 `.bad-<时间戳>` 并重建空计划，绝不因数据问题阻塞启动。

**为什么不用 SQLite（MVP 阶段）**：数据量极小，人的可读性和"我直接打开文件就能改"更重要；`store.py` 已做接口隔离，将来要统计/检索时换 SQLite 只需改一层。

## 6. 自启动方案

**采用启动文件夹快捷方式（无需管理员，可被任务管理器统一管理）。**

注册命令的核心等价形式（已在临时目录验证可生成）：

```powershell
$startup = [Environment]::GetFolderPath('Startup')
$lnk = (New-Object -ComObject WScript.Shell).CreateShortcut("$startup\今日待办.lnk")
$lnk.TargetPath       = 'D:\Learning\Anaconda3\pythonw.exe'
$lnk.Arguments        = '"C:\Users\13431\Documents\ChatGPT\开机代办\app\main.py" --autostart'
$lnk.WorkingDirectory = 'C:\Users\13431\Documents\ChatGPT\开机代办'
$lnk.WindowStyle      = 7
$lnk.Description      = '登录后询问今日待办'
$lnk.Save()
```

要点：

- `pythonw.exe` + `WindowStyle=7`：不出现控制台窗口。
- `--autostart` 参数让程序延迟 8 秒再弹窗（等桌面/IME 就绪），并且**出错只写日志、不弹错误框**。
- 验证方式：① `Get-Item` 确认 `.lnk` 存在；② 任务管理器 → 启动应用 里可看到并可禁用；③ 注销后重新登录实测窗口出现时间。
- 卸载：删除该 `.lnk`（或 `app/main.py --uninstall-autostart`），数据目录保留。
- 备选：`HKCU\...\Run` 注册表项（当前键不存在，可直接建）；若日后需要"登录后延迟 N 分钟""仅当天首次登录触发"等高级条件，再升级到任务计划程序。

## 7. 边界情况与防御

| 场景 | 处理 |
| --- | --- |
| 重复启动（多次登录/手动点开） | 命名互斥体单实例；第二个实例把已有窗口置顶后自行退出 |
| 进程被强杀/断电 | 输入变化即增量落盘（防抖 1~2 秒），最坏丢最后 1 条未提交内容 |
| 数据文件损坏 | 隔离为 `.bad-*` 并重建，不阻塞启动 |
| 跨天（凌晨 00:30 登录，或窗口开着过了午夜） | 以本地日期归属；窗口打开期间跨过午夜时提示"已进入新的一天"，可一键把未完成项带到新的一天 |
| 中文输入法 | tkinter 下 IME 正常，但需在按键处理里避免"选词回车"被当成提交（按 `keysym` + 输入法组合状态判断，需实测打磨） |
| 多显示器/分辨率变化 | 记住的坐标若超出当前虚拟屏幕范围，回落到主屏右下 |
| 首次安装即自启失败 | 日志记录；提供 `tools/install_autostart.ps1 -Verify` 输出诊断 |
| 无网络 / 无管理员 | 全流程不依赖，必须保证可用 |
| 依赖 Anaconda 环境 | 若担心以后动 Anaconda，可 PyInstaller 打包单文件 exe，自启动目标改为 exe，摆脱解释器路径 |

## 12. 实现说明（v0.1.0，已完成 M1 + M2）

代码已按本文档落地，与初版计划的差异只有三处，都是为了减少依赖与复杂度：

1. `core/schedule.py` 里原本设计的"一次性定时器"改成 **15 秒统一心跳**（跨天、稍后提醒、
   空闲收起、后台超时都由同一个 tick 驱动），少一套定时器状态，机器休眠唤醒后也不会漏触发。
2. `ui/` 由"录入窗口 + 清单窗口"两个文件合并为 **单窗口双模式**，避免同时出现多个窗口。
3. 平台层目录由 `platform/` 改名为 `host/` —— 否则模块名会遮蔽标准库 `platform`。

已实测通过的行为（以运行日志与自检结果为准）：

| 验证项 | 结果 |
| --- | --- |
| 自启动快捷方式创建 | ✅ 启动文件夹内 `.lnk` 指向 `pythonw.exe`，参数 `"...\app\main.py" --autostart` |
| 无控制台窗口 | ✅ `pythonw.exe` + `WindowStyle=7` |
| 首次弹窗 | ✅ 窗口正常出现并抢到焦点 |
| 稍后提醒 | ✅ 启动时处于提醒等待则保持隐藏，到点自动弹出 |
| 再次唤起 | ✅ 旧实例收不到新进程信号的问题已修复，现在会唤出原窗口 |
| 单实例 | ✅ 第二次启动只发信号后退出，系统里始终只有一个进程 |
| 数据持久化 | ✅ 22 项自检全部通过（含原子写、损坏文件隔离、顺延去重、Markdown 归档） |

新增的两个计划外但很实用的东西：

- `tools/selftest.py`：在临时目录里跑一遍数据层与界面层，改完代码先跑它，不碰正式数据。
- 环境变量 `TODAYTODO_DATA`：把数据目录指到别处，方便试用与回归测试。

## 13. 视觉与交互优化（v0.1.1）

### 13.1 深蓝立体主题

- 新增 `app/ui/theme.py`，集中管理配色与控件外观：窗口底色 `#0d1f33`、卡片 `#14304a`、
  输入区凹陷色 `#0b1a2b`、主色 `#2f7cf6`。
- 立体按钮 `Solid3DButton` 由"顶面 + 厚度边 + 高光描边"三层拼成，按下时顶面下沉 3 像素，
  悬停时顶面提亮；不需要任何图片资源。
- 复选框改为自绘 `Check3D`（凹陷方框 + 主色对勾），避免系统原生复选框在深色底上发白。
- 标题栏通过 DWM 一并染成深蓝。踩到一个坑：窗口刚 `deiconify()` 时外层 `TkTopLevel`
  句柄还没就绪，直接调用会静默失败（HRESULT `E_INVALIDARG`），因此改为多句柄尝试 + 自动重试。
- 滚动条改用 `clam` 主题自定义样式，否则深色界面上会出现一条浅色滚动条。

### 13.2 关闭逻辑

- 点右上角 ✕ 不再直接收起，而是弹出深蓝风格的选择框：
  **后台运行**（主按钮，默认回车键）/ **退出程序**（红色按钮）。
- 对话框按 Esc 或点右上角 ✕ 等于取消，窗口保持打开，不会误关。
- 主窗口按 Esc 仍然是"快速收起"，作为熟练后的快捷路径保留。
- 「稍后提醒 ▾」菜单里的"退出程序"已移除，退出只有一个入口，不再重复。
- 跨天提示原本用的是系统原生弹窗（浅色，与主题割裂），已换成同一个深色对话框组件。

### 13.3 窗口自适应

- 清单区高度跟随条目数量，最多长到 300 像素，超出才滚动。
- 首次弹出时按内容定高，并按右下角锚点回推坐标，避免变高后跑出屏幕底部。
- 新增配置 `auto_fit_height`（默认 `true`）：关掉它就回到固定高度、手动拖动，尺寸会被记住。

## 14. 优先级（v0.1.2）

### 14.1 交互定义

- 每条待办左侧有一个圆标，**点一下即按点击先后排定优先级**：
  第一个点的排第 1 位，第二个点的排第 2 位，以此类推。
- 再点一次已排优先级的圆标 = 取消，剩余的自动**紧凑续号**（不会留下 1、3 这样的空档）。
- 清单按优先级自动重排：有优先级的按序号排在前，没有的保持添加顺序。

### 14.2 视觉

- 优先级圆圈与整行左侧色条同色，颜色按优先级递减：

  | 优先级 | 1 | 2 | 3 | 4 | 5 | 6 及以后 |
  | --- | --- | --- | --- | --- | --- | --- |
  | 颜色 | 红 `#e5484d` | 橙 `#f76808` | 黄 `#ffb224` | 绿 `#30a46c` | 蓝 `#0091ff` | 紫 `#8e4ec6`（循环） |

- 未排优先级的圆标画得很淡，鼠标悬停才浮现蓝色 `+`，这样不会和左边的复选框抢注意力。
- 左侧色条对未排优先级的行依然占位（画成卡片同色），保证所有行的复选框竖直对齐。
- 已完成条目的文字仍用灰色加删除线，优先级色条保留，方便回看当天先做了什么。

### 14.3 数据

- `TodoItem` 新增 `priority` 字段，1 表示最高，`null` 表示未排；
  旧的计划文件没有这个字段也能正常读（读作 `null`）。
- 排序在展示层完成，**不改动 `items` 的存储顺序**，所以"添加顺序"这个信息不会丢，
  取消优先级后能回到原本的次序。
- Markdown 归档会在有优先级的条目前加 `[P1]` 标记。
